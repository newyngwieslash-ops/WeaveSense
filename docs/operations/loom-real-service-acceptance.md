## 执行中发现的两个真实问题

### 1. 模型网关不返回 token usage（重要）

所有成功调用（`model_calls: 1`、`status: succeeded`）的 `input_tokens` / `output_tokens` **均为 null**。

后果：
- **费用无法从账本核算**，只能依赖供应商账单；
- 预算熔断（T13 的保守预留机制）**只能依据调用次数**，不能依据金额；
- 这正是 T13 设计的 `unknown` 场景，但当时用假模型（返回 usage）无法暴露。

**这解释了此前 A 类手测"无法证明零费用"的困惑。**

### 2. 40 秒超时对真实推理偏紧

5 次调用中 3 次撞上 40 秒上限（成功率 2/5）。成功的那次用了 31—32 秒，说明**正常完成就在上限边缘**。

建议（**未擅自修改**）：把 `chat` 的超时从 40 秒放宽到 90—120 秒，或改为按请求大小动态调整。属产品参数变更，需你确认。

## 环境发现：本机 DNS 为 fake-IP 代理

所有公网域名解析到 `198.18.0.0/15`（RFC 2544），由本机代理接管真实连接。
T05 的 SSRF 防护**正确地拒绝**了该网段，导致初始采集全部被拦（`blocked_address`）。

**处理（经用户批准为方案 A）**：新增 `LOOM_EGRESS_CIDRS` 环境变量，允许运维**显式声明**出口网段：
- **默认关闭**：不声明时行为与之前完全一致（该网段仍被拒）；
- **仅声明生效**：只有列出的网段被放行；
- **永不放行**：loopback、link-local（云元数据）、未指定、多播**即使被声明也拒绝**；
- 含 6 项测试（26 项策略测试全通过）。

## 1. 超时复验：120 秒确实必要

| 次 | 结果 | 用时 | 材料 |
|---|---|---|---|
| #1 | ❌ `invalid_output` | **58.5 s** | 12,639 字符 |

**结论**：耗时 58—62 秒**远超原 40 秒上限**，证明调整方向正确（否则 #1/#2 会直接超时）。
但成功率仍 1/3——失败原因**从"超时"变成了"租约"**（见下），不是超时本身。

## 2. usage 缺失：根因是我们自己的代码（已修复）

**网关确实返回 usage**（实测 `/chat/completions`）：
```json
"usage": {"prompt_tokens": 7, "completion_tokens": 5, "total_tokens": 12,
          "prompt_tokens_details": {"cached_tokens": 0}}
```

**根因**：`src/lib/server/legacy-output.ts` 把 token 字段**硬编码为 null**：
```ts
input_tokens: null, output_tokens: null,   // 修复前
```
`chat()` 也从未读取响应的 `usage`。网关给了数字，代码**丢弃**了它。

**已修**：
- `analyze.ts` 的 `chat()`：提取 `usage.prompt_tokens` / `completion_tokens`
- `legacy-output.ts` 的 `runtime()`：**累加**记录（修正重试会二次计费，取最后一次会少算）
- 缺 usage 时保持 **null（unknown）**，不伪装成 0

测试 16/16（含"无 usage 仍为 null"反向用例）。

## 3. 两个失败模式的共同根因（离线定位，零成本）

**租约（`expires_at`）固定 60 秒，短于允许的工作时长。**

| 入口 | 调用预算 | × 单次上限 120 s | 旧租约 |
|---|---|---|---|
| analyze_item / briefing | 2 | 240 s | **60 s** ❌ |
| research（库内问答） | 6 | 720 s | **60 s** ❌ |

- #2（61.7 s）→ 超过 60 s ≠ 租约 → `completeRun` 的 `ownsRun` 检查 `expires_at > now` 失败 → 拒绝写入 → 上报 `persist_failed`
- #1（58.5 s，2 次调用）→ 首次调用耗尽租约、二次"格式修正"调用返回后租约已过 → 同一检查失败 → 上报 `invalid_output`
- #3（25.4 s）→ 在租约内 → 成功。**与实测完全吻合。**

**已修**：租约由调用预算推导，不再取整数值：
```ts
function runLeaseIso(maxModelCalls) {
  return new Date(Date.now() + maxModelCalls * 120_000 + 60_000).toISOString();
}
```
→ analyze_item / briefing **300 s**、research **780 s**。

测试断言的是**性质**（租约 > 最坏工作），而非模拟过期租约——后者只能复现缺陷、无法验证修复。
