## 用户先完成

1. 使用已有 Telegram 账号打开 [Telegram 开发者入口](https://my.telegram.org)，自行完成登录。
2. 进入 **API development tools**。已有应用就使用该应用；没有则按表单创建，用于自己的 Loom 采集客户端。
3. 妥善保存 `api_id` 和 `api_hash`。此处需要用户客户端凭据，不是 BotFather 的 bot token。
4. 在聊天中只回复“已准备好”，并提供首批希望采集的 1—3 个公开频道 `@用户名` 或链接。API hash、登录验证码、两步验证密码及会话文件不要发送到聊天。

官方说明：[获取 API ID](https://core.telegram.org/api/obtaining_api_id)。账号认证需要本人操作；凭据准备完成不等于 Loom 已登录。

## 助手后续执行顺序

1. 对用户选定频道确认范围；先做少量公开频道的文本增量验证，不自动加入私群、不扫描账号全部聊天，不启用 OCR/ASR 或自动分析。
2. 准备用户可直接输入的本地私密配置/登录入口；用户本人输入凭据、验证码和可能需要的两步验证密码，不经聊天传递。
3. 修正当前部署配置的凭据注入后再登录：根目录 compose 的 `environment` 把 `TELEGRAM_API_ID/HASH/SESSION` 缺省设为空，会覆盖 `env_file` 同名值。不能只修改 env_file 就宣称配置生效。现有保护配置须保留；仅重建必要服务，禁止占位口令、全栈重建或删除卷。
4. 使用现有 `workers/telethon/login.py` 与持久会话卷完成登录；登录前处理工作进程并发访问同一 SQLite 会话的问题，完成后重启目标 worker 并检查 `authorized=true`。不要输出账号标识或会话内容。
5. 证明应用实际走 Telethon 路径，而不是网页回退；核对部署 worker 是否含已验证分页修复。当前 worker 的 `resolve_channel()` 会尝试 `JoinChannelRequest`，即读取指定频道时可能加入该频道；采集前说明此行为并确认所选频道，或先改为纯读取，不能扫描用户未选定的频道。
6. 验证首轮入库、重复扫描不重复、新内容增量与游标；无新消息时标为待观察，不伪造增量通过。遇 FloodWait 退避。
7. 会话加入受保护备份范围；记录来源、时间、条数、错误和复验结果。达到这些条件后才更新 T21 的 Telegram 账号路径状态；不自动完成 T23。
